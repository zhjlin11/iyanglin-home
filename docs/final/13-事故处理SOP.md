# 杨林生活网 (iyanglin.com) 突发事故应急处置手册 (SOP)

## 1. 事故等级划分与上报时限

| 事故等级 | 影响特征 | 响应时限 | 解决时限 |
| :--- | :--- | :--- | :--- |
| **P0 致命事故** | 全站瘫痪白屏、核心数据库崩溃、全网支付无法付款 | 5 分钟内响应 | <= 30 分钟恢复 |
| **P1 严重事故** | 核心频道（招聘/房产/发布）无法提交、短信验证码大面积发送失败 | 15 分钟内响应 | <= 2 小时恢复 |
| **P2 局部事故** | 积分签到异常、某图片上传偶发失败、后台图表统计延迟 | 30 分钟内响应 | <= 6 小时恢复 |
| **P3 微小问题** | 页面文案错别字、个别移动端机型边距微小偏移 | 2 小时内响应 | 24 小时内修复 |

## 2. 典型事故应急处理预案

### 场景一：微信支付大面积掉单或用户已扣款但未到账
1. **即刻止损**：运维检查微信官方商户平台是否有系统故障公告；
2. **核验链路**：检查生产主机 Nginx 是否拦截了微信回调 POST 请求，查看 `/api/billing/webhook` 错误日志；
3. **手动补偿**：引导受影响用户在收银台点击「已支付？点此刷新」，系统调用 `/api/billing/verify` 主动向微信查单并补发权益；
4. **账目核平**：事后由财务比对对账单，确保每一笔到账均有对应的订单已标记为 `PAID`。

### 场景二：突发重大涉政/涉黄违规内容传播
1. **一键阻断**：登录后台进入系统设置，临时开启「全站内容发布强制人工审核」开关；
2. **紧急下架**：在管理后台输入违规关键词或用户 ID，执行全局软下架与封号；
3. **数据库取证**：提取发布者的注册手机号、登录 IP、操作时间戳，打包固定证据；
4. **应急大屏**：若事态极其严重，执行预置维护脚本，前台跳转“🛠️ 杨林生活网 · 系统例行维护中”大屏。

### 场景三：服务器 CPU 100% 或数据库连接池爆满
1. **排查慢查询**：执行 `docker exec vasto-postgres psql -U postgres -c "SELECT pid, query, state FROM pg_stat_activity WHERE state != 'idle';"`，识别卡顿的慢 SQL 并予以 `pg_terminate_backend`；
2. **重启应用守护**：执行 `pm2 reload yanglinol-newsite` 释放内存与闲置连接；
3. **临时限流**：在 Nginx 层面开启单 IP 并发请求限制 (`limit_req_zone`)，防御恶意 CC 攻击。

## 3. 事故复盘与免责文化 (Blameless Post-mortem)

每次 P0/P1 事故解决后 48 小时内，技术与运营团队必须召开复盘会，输出《事故复盘报告》：
- **时间线还原**：事故发现时间、响应时间、诊断时间、恢复时间；
- **根因分析 (5 Whys)**：探寻深层制度或技术设计短板，不归咎于个人操作失误；
- **改进 Todo**：制定代码加固、监控报警阈值调优、自动化测试用例补充等明确落地的改进行动项。
