## 2. 组织内部细分角色权能分配表

组织上下文强制通过服务端 `verifyOrgAccess(userId, organizationId, requiredRoles)` 进行鉴权校验。

| 角色代码 (Role Code) | 角色名称 | 核心职责与权限边界 | 越权防护规则 |
|---|---|---|---|
| `OWNER` | 组织创建者/法人 | 拥有组织全部最高权限，包括成员注销、资金提现、API Key 轮换、解散空间 | 唯一所有者，不可转让未授权第三方 |
| `ADMIN` | 组织管理员 | 管理团队成员、任务指派、职位发布、客户 CRM、查看经营数据大盘 | 严禁进行大额提现与空间解散操作 |
| `OPERATOR` | 运营专员 | 内容发布、营销活动报名、优惠券发放、便民需求跟进 | 仅限日常业务运营，无权限配置 API 密钥 |
| `HR` | 招聘主管 | 职位管理、候选人简历库筛选、面试排期安排、录用状态流转 | 仅限 ATS 招聘模块，严禁访问财务与交易订单 |
| `CUSTOMER_SERVICE` | 客服专员 | 客户线索跟进、工单答疑、评价解释回复、回访任务登记 | 手机号码动态掩码脱敏显示，无导出权限 |
| `FINANCE` | 财务专员 | 查阅订单交易流水、对账单下载、申请佣金结算发票凭证 | 仅限财务流转，严禁修改业务订单状态 |
| `TECHNICIAN` | 履约技师/师傅 | 查看指派给自己的工单详情、地址导航、上传完工照片、确认完工 | 仅限被指派的具体工单，无全盘客户列表权限 |

## 4. 开放平台 API 细粒度 Scope 授权规范

外部应用调用开放接口 (`/api/v1/open/*`) 时，必须在请求头携带 `Authorization: Bearer sec_live_...`，系统严格根据授权 Scope 实施频控与拦截。

| 权限作用域 (Scope) | 授权描述 | 允许调用的标准接口 | 限制说明 |
|---|---|---|---|
| `jobs:read` | 组织职位查询 | `GET /api/v1/open/jobs` | 仅返回当前组织发布的职位列表 |
| `jobs:write` | 组织职位发布与修改 | `POST /api/v1/open/jobs` | 必须携带组织有效身份，自动归属本租户 |
| `orders:read` | 履约订单拉取 | `GET /api/v1/open/orders` | 仅返回派发给本商户或本机构的订单 |
| `leads:read` | 商机线索拉取 | `GET /api/v1/open/leads` | 仅限已匹配并认领的商机线索 |
| `company:read` | 企业基本档案读取 | `GET /api/v1/open/company` | 企业入驻信息、认证状态、联系方式 |
| `*` (Full Access) | 组织全域最高集成权限 | 上述全部接口 | 仅组织 Owner 创建的高级应用凭据可申请 |
